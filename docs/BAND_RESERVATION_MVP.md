# BAND 예약 MVP

기준일: 2026-10-12

## 목적

11월 정식 출시 전 10월 동안 실제 고객 흐름과 운영 흐름을 검증하기 위한 정일품 정육식당 BAND 전용 예약 MVP다.

BAND는 제품 소개와 판매 공지를 담당하고, 예약 링크를 통해 이 웹앱으로 이동한다. 웹앱은 예약 수량, 생산한도, 예상 픽업시간, 수령 여부, 취소와 노쇼, 고객 재구매 이력을 기록한다.

10월 MVP는 **실제 예약금을 결제하지 않는 테스트 결제 모드**로 운영한다. 11월 정식 버전에서 카카오페이 실결제와 SendOn 거래안내 문자를 연결하는 것이 목표다.

## 고객 흐름

공개 경로: `/band-reserve`

1. BAND 판매글의 예약 링크로 접속한다.
2. 판매상품, 판매가, 남은 생산가능수량, 예약·픽업 일정을 확인한다.
3. 수량을 선택한다.
4. 이름과 휴대전화번호를 입력한다.
5. 예상 픽업시간을 선택한다.
6. 예약금·취소·환불 정책에 명시적으로 동의한다.
7. 10월 MVP에서는 실제 결제 대신 TEST PAYMENT로 예약을 확정한다.
8. 예약번호, 수량, 상품금액, 테스트 예약금, 픽업정보를 완료화면에서 확인한다.

회원가입, 비밀번호, 장바구니, 포인트, 쿠폰은 MVP에 포함하지 않는다.

## 예상 픽업시간

다음 구간 중 하나를 선택한다.

- 10:00~12:00
- 12:00~14:00
- 14:00~16:00
- 16:00~18:00
- 18:00 이후
- 아직 모름

선택값은 생산자와 픽업 현장의 작업량 예측을 위한 참고값이다. 고객이 해당 시간을 반드시 지켜야 하는 예약 슬롯으로 취급하지 않는다.

## 생산한도

웹앱은 완제품 재고가 아니라 회차별 `production_limit`을 관리한다.

예:

- 최대 생산수량: 60개
- 확정 예약수량: 42개
- 잔여 예약가능수량: 18개

예약 생성 시 `band_sales.reserved_qty`를 조건부로 증가시켜 생산한도를 초과하는 요청을 거부한다.

MVP 구현은 단일 SQL `UPDATE ... WHERE reserved_qty + ? <= production_limit RETURNING ...`으로 수량을 확보한 뒤 예약을 저장한다. 예약 저장 실패 시 확보한 수량을 복원한다.

고객 요청에는 고유 idempotency key를 사용해 네트워크 재시도나 빠른 이중 제출이 동일 예약을 중복 생성하지 않도록 한다.

## 예약금·취소·환불 정책

정식 출시 목표 정책:

- 예약금은 상품 1개당 기본 1,000원이다.
- 예약금은 수령 시 최종 상품금액에서 차감한다.
- 생산확정 전 고객 취소: 예약금 환불 대상
- 생산확정 이후 고객 사유 취소: 예약금 환불 없음
- 수령 당일 고객 사유 취소: 예약금 환불 없음
- 노쇼: 예약금 환불 없음
- 정일품 사유로 상품 제공 불가: 전액 환불

고객은 예약 전에 별도 체크박스로 정책에 동의해야 한다. DB에는 정책 버전과 동의시각을 기록한다.

10월 MVP의 `payment_provider=test`, `payment_status=test_paid`는 실제 금전 거래를 의미하지 않는다. 취소 시 `test_refunded` 또는 `forfeited` 상태만 시뮬레이션한다.

## 운영자 흐름

보호 경로: `/band-admin`

기존 운영 암호 세션을 사용한다.

### 판매회차

운영자는 다음을 입력한다.

- 상품
- 표시 상품명
- 판매가
- 최대 생산수량
- 상품당 예약금
- 예약 시작시각
- 예약 마감시각
- 생산 확정시각
- 픽업일
- 픽업 시작·종료시각
- 픽업장소

새 회차를 활성화하면 이전 활성 회차는 비활성화한다.

### 예약현황

운영자는 다음을 확인한다.

- 생산한도
- 예약수량
- 잔여수량
- 예상매출
- 고객명과 휴대전화
- 예약수량
- 예상 픽업시간
- 예약금 상태
- 예약상태

예약상태는 MVP에서 다음으로 처리한다.

- `confirmed`
- `picked_up`
- `cancelled`
- `no_show`

생산확정 전 취소는 생산한도를 복원한다. 생산확정 후 취소는 이미 생산에 반영된 수량으로 보기 때문에 회차의 예약수량을 되돌리지 않는다.

## 고객 DB

휴대전화번호를 고객 식별 기준으로 사용하고 BAND 예약 이력을 집계한다.

MVP 화면에는 다음을 제공한다.

- 총 예약횟수
- 정상수령 횟수
- 취소 횟수
- 노쇼 횟수
- 정상수령률
- 누적 정상수령 수량
- 누적 정상수령 금액

초기 자동 라벨:

- 정상수령 0~1회: 신규
- 정상수령 2~4회: 재구매
- 정상수령 5회 이상: 단골
- 노쇼 2회 이상: 노쇼주의

이 라벨은 10월 데이터가 쌓인 뒤 실제 분포를 보고 조정한다. 고객 DB는 광고문자 발송용으로 사용하지 않는다.

## 문자 원칙

10월 MVP에는 SendOn 실연동을 포함하지 않는다.

11월 정식 버전에서 SendOn을 연결할 경우 거래 수행에 필요한 문자만 전송한다.

- 예약확정
- 수령일 오전 픽업 안내
- 필요 시 픽업 마감 전 미수령 고객 안내
- 취소·환불 완료

신상품, 할인, 판매예고 등 광고성 정보는 문자로 보내지 않고 BAND에서만 공지한다.

## API

| Method | Route | 접근 | 목적 |
|---|---|---|---|
| GET | `/api/band-sales` | 공개 | 현재 활성 판매회차 |
| GET | `/api/band-sales?admin=1` | 운영자 | 판매회차와 상품목록 |
| POST | `/api/band-sales` | 운영자 | 판매회차 생성 |
| PATCH | `/api/band-sales` | 운영자 | 회차 상태 변경 |
| POST | `/api/band-reservations` | 공개 | 테스트 예약 생성 |
| GET | `/api/band-reservations` | 운영자 | 예약목록 |
| PATCH | `/api/band-reservations/:id` | 운영자 | 수령·취소·노쇼 처리 |
| GET | `/api/band-customers` | 운영자 | 고객 예약 이력 집계 |

## 데이터 테이블

### `band_sales`

회차별 상품, 가격, 생산한도, 누적 예약수량, 예약금, 예약/생산/픽업 일정을 보관한다.

### `band_reservations`

고객 예약과 테스트 결제상태, 정책 동의, 취소·수령·노쇼 시각을 보관한다.

`reservation_no`와 `idempotency_key`는 각각 unique다.

### `band_reservation_events`

예약 상태 변경의 감사 이벤트를 append-only로 저장한다.

## 10월 MVP에서 의도적으로 제외한 기능

- 실제 KakaoPay 승인·취소 API
- 10분 결제 hold
- 실제 SendOn SMS
- 고객용 예약조회·셀프취소
- 대기예약
- 복수 상품 장바구니
- VIP/RFM 고급분석
- BAND 자동게시
- 화려한 브랜드 디자인

## 11월 정식 출시 전 필수 후속작업

1. KakaoPay 가맹점 연동과 실결제
2. 결제 중 생산수량 10분 hold와 만료 복구
3. 생산확정 전 카카오페이 전체·부분 취소
4. SendOn 예약확정·픽업 안내
5. 고객 셀프 예약조회와 환불가능 시점 전 취소
6. 모바일 실기기 테스트
7. 실제 동시예약 부하 테스트
8. 최종 브랜드 디자인과 상품사진 규격 확정
9. 개인정보·취소환불 고지 최종 검토
10. 10월 데이터로 고객등급과 예약정책 재조정

## MVP 성공 기준

- 회원가입 없이 1분 안에 예약 가능
- 예약 누락과 중복 생성 없음
- 생산한도보다 많은 예약이 저장되지 않음
- 운영자가 수령·취소·노쇼를 즉시 기록 가능
- 픽업시간대 분포 확인 가능
- 휴대전화 기준 고객 이력이 누적됨
- 기존 BAND 댓글예약보다 운영자의 수량 합산 업무가 감소함
