# 제품 개요

## 목적

정일품 운영 웹앱은 고객의 선물세트 주문부터 판매장 확인, 작업장 생산, 수령·배송, 결제·외상, 감사이력까지 하나의 D1 데이터 흐름으로 연결한다.

## 사용자

- 고객: 키오스크에서 상품 또는 맞춤주문을 접수한다.
- 판매장 운영자: 주문, 고객도착, 결제, 외상, 일정 미지정 주문을 관리한다.
- 작업장 운영자: 작업 우선순위, 상태, 생산량, 패키지를 관리한다.
- 관리자: 상품, 판매기간, 제품사진 URL, 키오스크 안내문구를 수정한다.

## 제품 영역

| 영역 | 대표 route | 책임 |
|---|---|---|
| 고객 키오스크 | `/`, `/kiosk`, `/kiosk/custom` | 상품선택, 방문/택배, 맞춤주문, 주문접수 |
| 판매장 | `/sales` | 날짜별 주문표, 검색, 고객도착, 결제·외상, legacy 일정 지정 |
| 작업장 | `/workshop` | 작업수락, 작업시작, 준비완료, 긴급도, 상품별 생산량 |
| 생산·패키지 | `/workshop/production`, `/workshop/packages/:code` | BOM, Batch, Skin Pack, QR, 라벨, 패키지 조립 |
| 설정 | `/settings` | 상품, 판매기간, 사진 URL, kiosk headline |

## 핵심 업무 흐름

```text
고객 주문
→ orders/order_items/fulfillments DB commit
→ 판매장 날짜별 목록
→ 고객도착·결제·상태 관리
→ 작업장 작업수락·시작·준비완료
→ BOM 기반 생산·Skin Pack·Package
→ 판매장 전달 또는 택배 출고
→ 모든 주요 변경을 audit event로 보존
```

## 제품 원칙

- D1을 운영 데이터의 단일 원본으로 사용한다.
- 고객 주문완료는 DB commit 성공 후에만 표시한다.
- 방문수령과 택배 일정을 fulfillment로 정규화한다.
- 기존 주문과 감사이력을 삭제하지 않는다.
- 고객 화면은 쉽고 큰 입력 동선을 유지한다.
- 판매장 화면은 고밀도 날짜별 주문표를 유지한다.
- 작업장 화면은 금액보다 작업 우선순위와 생산 상태를 우선한다.
- 시즌 문구는 코드에 고정하지 않고 설정값으로 관리한다.

## 현재 적용 범위

Production Version 20에는 키오스크, 판매장 연동, 작업장 화이트보드, 설정, 결제·외상, 공통 navigation이 배포되어 있다.

최신 로컬 통합본에는 추가로 BOM, Production Batch, Skin Pack, 패키지 QR/라벨/재배정이 포함되어 있다. 이 기능은 migration 0005와 함께 검증됐지만 아직 Production에 적용되지 않았다.

## 명시적 비범위

- 실제 PG·카드 승인
- SMS·카카오 알림 발송
- GPT 기반 추천·자동응답
- Supabase/Vercel 기반 운영
- 제품사진 파일 업로드 저장소
- 바코드·라벨 프린터 장치의 직접 제어

QR 생성, HID 입력, Open Label CSV 파일 생성은 지원하지만 외부 장치나 Open Label API와 직접 통신하지 않는다.
