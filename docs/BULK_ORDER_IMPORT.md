# 대량 택배 주문 엑셀 업로드

## 사용자 흐름

1. 운영자가 `/bulk-orders`에서 운영 암호를 확인한다.
2. `엑셀 양식 받기`로 제공 양식을 내려받는다.
3. `주문입력` 시트 6행부터 주문을 작성한다.
4. `.xlsx` 파일을 선택하면 브라우저가 열 이름과 행 값을 읽고 오류와 주문 묶음을 표시한다.
5. 오류가 없을 때 `일괄 주문 업로드`를 누르면 서버가 현재 상품·가격·한정수량을 다시 확인하고 주문을 저장한다.

## 엑셀 계약

`주문입력` 시트 이름과 5행 열 이름은 변경하지 않는다. 한 행은 상품 하나다.

| 열 | 필수 | 규칙 |
|---|---:|---|
| 주문그룹키 | O | 같은 주문의 상품 행에 같은 값을 반복한다. 최대 60자다. |
| 주문자명 | O | 같은 그룹에서 모두 같아야 한다. |
| 주문자연락처 | O | 0으로 시작하는 10~11자리다. 하이픈은 허용한다. |
| 수령인명 | O | 같은 그룹에서 모두 같아야 한다. |
| 수령인연락처 | O | 0으로 시작하는 10~11자리다. 하이픈은 허용한다. |
| 우편번호 | O | 5자리 숫자다. 숫자로 읽힌 4자리 값은 앞에 0을 보완한다. |
| 도로명주소 | O | 5자 이상이다. |
| 참고주소 |  | 주소 검색의 참고 항목이다. |
| 지번주소 |  | 필요한 경우만 입력한다. |
| 상세주소 | O | 빈 값이면 접수하지 않는다. |
| 발송일 | O | `yyyy-mm-dd`, 한국 기준 오늘 이후다. |
| 상품코드 | O | 현재 활성 상품코드여야 한다. 같은 그룹의 같은 코드는 수량을 합친다. |
| 수량 | O | 1~999 정수다. |
| 주문메모 |  | 같은 그룹에서 모두 같아야 한다. 최대 500자다. |

한 파일은 최대 200행, 주문그룹 100건, 5MB다. `.xls`와 CSV는 지원하지 않는다.

## 저장 계약

- `POST /api/orders/bulk`는 운영 세션을 요구한다.
- 브라우저가 파일 SHA-256을 계산하고 서버는 `파일 해시 + 주문그룹키`로 주문별 idempotency key를 만든다. 같은 파일 재업로드는 기존 주문을 반환한다.
- 모든 행·상품·한정수량을 먼저 검증한다. 이 단계에서 오류가 있으면 주문을 하나도 저장하지 않는다.
- 각 주문은 `orders`, `work_items`, `work_item_events` 변경을 하나의 D1 `batch()`로 저장한다. 한 주문 저장 실패가 이미 완료된 다른 주문을 되돌리지는 않으며, 같은 파일을 다시 올리면 실패한 주문만 재시도한다.
- 가격은 엑셀에서 받지 않고 업로드 시점의 활성 상품 가격을 사용한다.
- 주문은 `unpaid`, 작업은 `delivery`·`received`, 발송일은 `YYYY-MM-DDT00:00:00+09:00`으로 생성한다.
- 감사 이벤트에는 업로드 출처와 행/상품 개수만 남긴다. 주문자·수령인·연락처·주소는 이벤트 JSON과 서버 로그에 기록하지 않는다.
- 파일 내용은 브라우저 메모리에서만 다루며 localStorage나 sessionStorage에 저장하지 않는다.

## 운영 주의사항

- 업로드 결과에서 `기존 접수`는 같은 파일의 같은 주문그룹키가 이미 저장된 경우다.
- `접수 실패`가 있으면 원본 파일을 그대로 다시 업로드한다. 이미 접수된 주문은 중복 생성되지 않는다.
- 결제 완료·부분결제 기록은 자동 생성하지 않는다. 접수 후 판매장 주문 상세에서 처리한다.
- DB schema와 migration 변경은 없다.
